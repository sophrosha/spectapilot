# Moza Wheel Control

Консольное приложение (.NET 8, без сторонних библиотек) для управления колёсным
сервоприводом **MOZA R3** через официальный MOZA SDK: плавное движение к углу,
удержание (hold) с плавным нарастанием, режим клавиатуры, UDP-сокет (Фаза 2)
и демо-сценарий автоЕзды (`demo`).

---

## ⚠️ Запуск — только от имени администратора

Это подтверждено диагностикой:

- обычный пользователь: SDK падает на `RS21::direct_input::Device::acquire`
  с `0x80070005 Access is denied` → `effect.start()` не запускается;
- **от администратора: всё работает** (официальная C++-проба: `START OK`, руль двигается);
- сам DirectInput, драйвер, Pit House и права на устройство исправны —
  отказ рождается внутри SDK 1.0.1.8 (это его особенность, а не поломка системы).

Способы запуска:

1. **`run_elevated.cmd`** рядом с `WheelControl.exe` (двойной клик → UAC);
2. правый клик по `WheelControl.exe` → «Запуск от имени администратора».

Также **должен работать MOZA Pit House** — SDK без него не находит устройство
и при необходимости перезапускает его сам.

**Второе условие старта: руль в центре (0°).** Найдено опытным путём: если в момент
запуска угол ≠ 0, SDK падает с тем же `Access is denied`. Приложение само читает угол
и повторяет запуск: увидите `! Руль повёрнут на X° — SDK стартует только с центра (0°)` —
поверни руль в центр, подключение продолжится автоматически (до 6 попыток).

**Один инстанс.** Повторный запуск программы закрывает уже работающий экземпляр
(в консоли нового: `Закрыт предыдущий экземпляр [...]`), чтобы два процесса не
дрались за FFB-эффект.

## Сборка и публикация

```powershell
dotnet build -c Release            # bin\Release\net8.0-windows\
dotnet publish -c Release -o publish   # publish\ (переносимая папка)
```

Нужен только .NET 8 SDK. Перед запуском после правок — всегда пересобирайте
(устаревшая сборка падает на давно исправленном `getDeviceParent`).

## Запуск

```powershell
.\publish\WheelControl.exe                    # реальный руль (от администратора!)
.\publish\WheelControl.exe --simulate         # симуляция, руль не трогается
```

Старт: `Waiting for device...` → `Connected device: [ID]`.
Если устройство не найдено — консоль сама предложит режим симуляции (не падает).

## Команды (режим клавиатуры — по умолчанию)

| Команда       | Действие |
|---------------|----------|
| `45`          | повернуть к углу: **физические градусы** (0° = центр, шкала ±N = реальный ход из Pit House: база 180° → ±90, 2700° → ±1350). На сокет не влияет — там своя шкала (см. `userFullLockDeg`) |
| `+30` / `-30` | сдвиг относительно текущего положения (**только в консоли**; в сокете «-30» = позиция) |
| `hold [угол]` | удержание в **физических градусах**: `hold 90` = ровно 90° реального поворота при ЛЮБОЙ базе Pit House (база 180° → это упор, 2700° → середина хода); нарастание ~300 мс; без аргумента — текущая позиция; лишние градусы клампятся и печатается реальная цель |
| `release`     | снять удержание |
| `demo [сек] [ампл.°]` | автодемо езды: змейка на полный ход руля, 50 с по умолчанию; сопротивление активно всё время (можно взять руль в руки); заканчивается само в центре либо любой командой move/hold/release |
| `status`      | позиция/цель/режим/demo |
| `socket`      | включить UDP-сервер (Фаза 2) |
| `keyboard`    | вернуться в режим клавиатуры |
| `sleep N`     | пауза N мс |
| `log [сек]`   | CSV-лог петли 200 Гц → `osc_log.csv` рядом с exe (10 с по умолчанию): позиция, скорость до/после фильтра и сырая SDK (`velRaw`, `velSdk`, `velFilt`), цель, сила — диагностика раскачки |
| `help`        | список команд |
| `exit`        | выход (момент всегда обнуляется) |

## Режим сокета (Фаза 2) — только UDP

Команда `socket` поднимает UDP-слушатель на `socketHost:socketPort`
(по умолчанию `127.0.0.1:7777`) — TCP не используется. Если включён
`socketAutoStart: true`, сервер стартует сам при запуске программы.

Каждая датаграмма = одна команда. **Числа — абсолютные углы вашей шкалы (±90):
`90` = упор, `0` = центр, «-5» = левее центра** (в консоли «-5» — это сдвиг,
из сокета — позиция; явный «+5» — сдвиг везде). Формат отправки мода Lua
подходит без изменений:

```lua
cfg.udpSocket:send(tostring(round(_G.spectapilot_steering)))
```

**Что делает сокет со значениями из игры:**

- **`invertSocket: true`** — знак числа инвертируется (если руль в игре крутится
  в обратную сторону относительно реального). Консольные команды не трогает.
- **`socketHandsMode: true`** — режим «держи меня за руки»: каждая позиция из игры
  удерживается жёсткой пружиной с силой `holdForce` (100%) — оттолкнуть руль от
  цели сложно, реакция мгновенная. Выключается `socketHandsMode: false` или
  командой `release` (до следующего пакета).
- **Дедуп**: повтор одного и того же числа («90 90 90») отсекается — принимается
  только новое значение.
- **Консольный перехват**: `hold`/угол ИЗ консоли переставляет цель, и сокет её
  больше не трогает до `release` (или повторного `socket`) — «hold 10» во время
  игры остаётся «hold 10». Пока сокет ждёт, печатается
  `-> сокет ждёт: руль под консолью … release, чтобы вернуть игру`.

Проверка из PowerShell:

```powershell
$u = New-Object Net.Sockets.UdpClient('127.0.0.1', 7777)
$b = [Text.Encoding]::UTF8.GetBytes('45')   # позиция 45 (инвертируется в -45 при invertSocket)
[void]$u.Send($b, $b.Length)
$b = [Text.Encoding]::UTF8.GetBytes('0')     # в центр
[void]$u.Send($b, $b.Length)
```

Ввод 30 Гц без задержки: для сокета время сглаживания = `socketSmoothTimeMs` (50 мс
по умолчанию вместо 500), цикл 200 Гц ведёт руль по актуальной позиции —
«последний побеждает», отклик почти мгновенный.

## Устранение неполадок

- **`Access is denied` / не запускается** → запустите от администратора **и поставьте
  руль в центр (0°)** — SDK требует и то, и другое (см. раздел запуска выше).
- **`Waiting for device...` висит** → запущен ли Pit House, подключён ли руль;
  через ~10 с консоль предложит симуляцию — соглашайтесь, если тестируете ввод.
- **Углы клампятся ±N°** → это реальный ход руля из Pit House (база 180° → ±90).
  Консоль всегда в физических градусах; если базу увеличишь в Pit House — и кламп,
  и `hold N` станут отсчитываться от нового хода автоматически.
- **Руль не возвращается в ноль / «не читает угол»** → смотрите, нет ли предупреждения
  `угол руля не обновляется N мс` — тогда перезапустите программу. Ввод из сокета
  теперь быстрый (`socketSmoothTimeMs: 50`), минусовые числа из сокета — позиции.
- **Руль в игре крутится в обратную сторону** → `invertSocket: true` в config.json
  (инвертирует числа из игры; консоль не трогает). Если направление стало верным
  после правки мода — поставь `false`.
- **Сокет не запускается / нужен свой адрес** → `socketHost`/`socketPort` в config.json;
  `socketAutoStart: true` — сервер поднимается сам при старте.
- **Руль в сокет-режиме легко оттолкнуть** → проверь `socketHandsMode: true`
  (режим «держи меня за руки», сила = `holdForce: 100`).
- **Руль раскачивается и стучит об упор на удержании** → (а) это могла быть старая сборка
  (slew-лимитер силы в петле — убран); обнови exe. (б) Свежая сборка дополнительно
  починила частоту петли: Windows держала `PeriodicTimer` на 15.6 мс (64 Гц вместо
  200) — теперь `timeBeginPeriod(1)`, петля реальные 200 Гц. (в) Если качается
  и дальше — запусти `log 10` во время раскачки: `publish\osc_log.csv`
  (позиция/скорость/сила 200 Гц) — по нему видно причину.
  Плавность даёт EMA цели hold (`socketSmoothTimeMs`, при необходимости 50 → 100).
- **`hold 10` не держит — руль уходит туда, куда шлёт игра** → консольный перехват:
  сокет ждёт до `release` (печается «сокет ждёт: руль под консолью…»); после
  `release` управление снова у игры.
- **Масштаб от Pit House** → база N° sweep = физ ход ±N/2 (180→±90, 300→±150 —
  строка `Motor limits:` печатает и базу, и шкалы: консоль = физ, сокет/игра =
  `userFullLockDeg`). Консоль пересчитывается сама при смене базы; `userFullLockDeg`
  — только единицы чисел из игры, физический ход не меняет.
- **Грузовик: руль в игре крутится 3 круга, а физический стоит «дубнем»** → ввод
  из игры обрезается шкалой (половина хода уже на упоре). Проверка: `status` →
  `sock: max ±N из игры (шкала ±M)`; если max упирается в шкалу — печатается
  подсказка «подними userFullLockDeg». Сейчас в конфигах `180` (90 физ = 180 в игре).
- **Руль дёргается / поддёргивания на змейке** → оставьте `smooth: true`;
  демпфер hold усилен (полная сила при 180 °/с) — гасит рывки при резких движениях.
- **Мелкое дерганье «как шестерня» при вращении руками** → исправлено: в контрол
  идёт **скорость SDK** (`fSteeringWheelVelocity`; единицы и знак проверены по
  логам — совпадает с производной позиции, ±400 °/с), запас — скользящее окно
  ~40 мс по позиции, если прошивка отдаёт выброс 0. EMA + мёртвая зона с
  гистерезисом 7/3 °/с (на **входе** фильтра: включение >7, отпускание <3 — на
  малых движениях демпфер не щёлкает вкл/выкл) гасят шум квантованной позиции:
  шаг 0.2° даёт ~5 °/с вместо 40 °/с, и демпфер не пульсирует силой. В логе три
  колонки для сравнения:
  `velRaw` (окно), `velSdk` (SDK), `velFilt` (то, что видит демпфер).
- **Дрожания/дёрганья на `hold 10` и на змейке** → исправлено (по логу
  `demo 50 100`: рывки силы до ~12000 за тик, руль съезжал с цели на ±7°,
  колебания ~6 Гц). Две причины: (1) мёртвая зона зануляла само состояние EMA —
  `velFilt` залипал в 0, пока |скорость| < 20 °/с (до 70 мс), и демпфер
  вырубался-включался рывком; (2) 40-мс окно + EMA давали демпферу запаздывание
  ~58 мс — на 6 Гц фазовый сдвиг >90°, и он подпитывал колебания вместо гашения.
  Лечится этой же сборкой: скорость — свежая `velSdk`, мёртвая зона — на входе
  EMA (включение демпфера плавное). Осталось — `log 10` и присылай CSV.
- **Микроступеньки из мода (мод шлёт целые градусы)** → ведение цели с опережением
  (lead): цель скользит плавно и синхронно с игрой: на медленном потоке сглаживание
  вдвое мягче, на быстром — не копит задержку (`socketSmoothTimeMs` — база τ,
  `LeadMaxDeg` ограничивает упреждение). Проверено смоуком v6 (ступеньки не
  залипают), ощущения на железе — сообщи, как пойдёт.
- **Руль резко дергается в случайных местах при езде** → исправлено: петля
  иногда вставала на десятки–сотни мс (хич системы/игры, антивирус на записи
  лога), а после возобновления сила прыгала в упор — руль хлестал через цель.
  Теперь: (1) после такой дыры сила плавно (~80 мс) доезжает до свежего
  значения вместо рывка; (2) лог пишется буфером 64 КБ (сбросы редкие);
  (3) процесс держится с приоритетом AboveNormal, чтобы игра не вытесняла
  петлю. Если осталось — `log 120` во время езды и присылай CSV: дыры видны
  как скачки `ms` больше 25 в колонке времени.
- **Дёрганья на конце угла / руль «липнет и отрывается» на змейке** → две причины:
  (1) наш крен (lead) вылезал за физический упор и ветрил пружину в стенку —
  клампнут к ходу руля; волна ~10 Гц (сила гудит в унисон со скоростью) ушла
  после ускорения фильтра скорости (EMA α 0.5). (2) Остался «лип-отрыв» — это
  трение Pit House: подтверждено логом — при «Естественном трении» >0 змейка
  даёт рывки (44 события/4.5 с), при 0 — ноль за 28 с. Выставь трение **0**
  (и «Интерполяцию FFB» **0** — значение 10 давало ступенчатость), инерцию
  держи на 200, инерцию руля не трогай — это вес руля.
- **Минимальные подёргивания при быстрой погоне (волна ~15 Гц, помеха раз в
  несколько секунд)** → это резонанс цепи Pit House, не наша петля (по логу: наш
  демпфер её только гасит, энергия идёт со стороны драйвера). Наш вклад минимизирован
  (демпфер раскрывается при 180 °/с — было 150). Источник ищем по одному параметру
  за прогон: «Демпфирование от скорости» 35 → 0, затем «Натуральное демпфирование»
  60 → 0, затем «Натуральная инерция» 200 → 100. Каждый прогон: `demo` + `log 60`,
  прислать CSV — по амплитуде волны видно, какой параметр источником.
- **Руль при отпускании / после скачка цели «ракетой» улетает в центр** → был
  разгон до 697 °/с (лог езды: цель −95 → 0). Теперь пружина ограничена силой
  удержания до сложения с демпфером — подлёт сам по себе ограничен 180 °/с при
  любой ошибке; на обычной работе (ошибка < 8°) поведение прежнее.
- **Малые повороты — «шестерня», большие плавно; пальчиком медленно опускаешь —
  подрагивает** → три источника: (1) щелчки демпфера на границе мёртвой зоны —
  теперь гистерезис 7/3 °/с (на малых движениях вкл/выкл было 3.3 раза/с);
  (2) мигания целых градусов из игры A↔B — теперь подавлены дебаунсом на один
  пакет (подтверждается повтором; толчки силы 267..716 из лога уходят);
  (3) **трение Pit House**: «Естественное трение» 50 и «Интерполяция FFB» 10 —
  лип-отрыв после нашей команды в CSV не виден, но на малых скоростях это
  классическая «шестерня» (п.37: трение 0 → ноль рывков за 28 с). Поставь 0/0.
  Пружину мягче без пересборки: `kpScale` в `config.json` (0.5 = вдвое мягче,
  1.0 = прежняя), демпфер: `kdScale` (1.0 = прежний; **<1 вернёт волну 15 Гц**).
  Момент 100% → 80% можно крутить через `maxTorque` — это твой сетап.
- **Слишком/мало сильное удержание** → `holdForce` в `config.json` (100 = максимум);
  жёсткость отдельная: полная сила пружины раскрывается уже при ошибке 8°
  (`HoldSpringFullDeg` в коде). `holdRampMs` — мягкость старта.
- **UDP-портом занят** → `socket` сообщит об ошибке; поменяйте `socketPort`
  в `config.json` (и в моде Lua).
- **Падение `AccessViolationException` в `getDeviceParent`** → вы используете
  устаревшую сборку; пересоберите (в коде эта функция не вызывается).
- При любых выходах/ошибках момент принудительно обнуляется
  (`setMagnitude(0)` → `stop()` → `stopForceFeedback()`), руль расслабляется.

## Структура

- `Program.cs` — точка входа, ожидание устройства, диспетчер команд, завершение;
- `Wheel.cs` — обёртка SDK: подключение, цикл 200 Гц, hold, безопасное завершение;
- `Config.cs` / `config.json` — конфигурация;
